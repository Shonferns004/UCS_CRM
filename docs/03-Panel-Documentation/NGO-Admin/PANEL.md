## 1. Panel Overview

- **Route base:** `/ngo-admin/*` (Verified — `client/src/panels/ngo-admin/NgoAdminPanel.jsx`).
- **Entry component:** `NgoAdminPanel` (same file).
- **Access control:** guarded for `admin` (and by extension privileged) roles. The panel's own `api/auth.js` enforces `admin`/`super_admin`; the shared `ProtectedRoute` in `client/src/App.jsx` maps `/ngo-admin/*` to `ROLE_PATHS.admin`. Privileged users (super_admin / master / admin) additionally get the "Show all codes (all NGOs)" toggle on the Acting-FRO Codes screen (Verified — `pages/Codes.jsx`).
- **Purpose:** operational management for an NGO team — FRO/station administration, donor master data, attendance, targets, field-monitoring dashboards and ticket/chat support.
- **Layout:** left nav with 7 items, a global master-search bar with live dropdown (donors / FROs / stations) wired to `masterSearch`, plus a team meeting-mode toggle and logout-All-FROs control (Verified).

## 4. Technical Implementation

- **Stack:** React function components + hooks, React Router, `lazy()` + `Suspense`; charts via **recharts** (PieChart) and icons via **lucide-react** (Verified — Dashboard.jsx imports).
- **API helper:** `client/src/panels/ngo-admin/api/auth.js` exports `apiGet/apiPost/apiPut/apiPatch/apiDelete` plus `masterSearch`, `getFroHourlyPerformance`, `getFroDailyStats`, `getStationWiseCollection`, `getTeamWiseCollection`, `listImpersonationCodes`, `listAllImpersonationCodes`. All calls use `_prefix: 'ucs'` and the shared fetcher from `client/src/api/auth.js` (token header, 401 → `/login`). Panel-facing paths keep an `/ngo-admin` prefix; shared go through `attendance`, `settings`, `causes`, `targets` etc.
- **Real-time:** dashboard subscribes via `onDbChange` from `lib/socket`; polling hooks (`usePolling`) drive live panels (Verified imports).
- **State/side stores:** `meetingStore` (`../../../meetingStore`) drives the meeting-mode toggle for the team (Verified import); shared components (`ChatWorkspace`, `TechnicalTickets`, `DonorDetailModal`, `Toast`, `SkeletonDashboard`) reused across panels (Verified).
- **Time handling:** IST-based date helpers (`istMonthKey()`, `toIstDate()`, `toLocaleString('en-US', { timeZone: 'Asia/Kolkata' })`) used for month keys and range boundaries (Verified — Dashboard.jsx).
- **Server side:** `backend/src/routes/ngoAdminRoutes.js` mounted at `/api/ngo-admin`, backed by `backend/src/controllers/ngoAdminController.js` (~7.5 k lines, ~92 exports) covering dashboard, stations, FRO management, master-search, targets, transfers, suspense and rejected-leads. Mount verified in `backend/src/index.js` line 273.

## 5. Business Logic

- **Search:** requires ≥2 characters; results grouped donors – stations (– FROs); donor rows open a `DonorDetailModal` (Verified).
- **Codes:** single-use 4-digit codes, TTL 5 minutes; status derived from `is_used` / `expires_at`; created by the FRO app switching Acting FRO; privileged roles can view across all NGOs (Verified — `pages/Codes.jsx`).
- **Targets:** monthly, keyed by `month` in IST; CRUD via `/ngo-admin/targets` (GET) and `/ngo-admin/targets` (POST) (Verified).
- **Bulk rename:** staged as `dry_run: true` list → review via `/rename-log` → commit with `dry_run: false, confirm: true` (Verified — StationManagement.jsx).
- **Deletions (non-connected fresh & assigned donors):** dry-run preview first for counts, then confirm POST (Verified).
- **Transfers:** list transfers and a "return early" action (Verified POST `/transfers/:id/return-early`).
- **Suspense linking:** search donor by name (debounced ≥2 chars) → link via `PUT /suspense/:id/link-donor`, or "No Match" → sent back to Accounts as verified (Verified — `pages/Suspense.jsx`).
- **Performance panels:** High/Low performance read the org-wide leaderboard, gate on punch-in, and Low Performance defaults to the "present" list (Verified — Dashboard.jsx comments/state).
- **Station family mapping:** station code prefix before the dash decides the family; old vs new = BOD/BFD (BSCT), AOD/AFD (AFLF), MOD/MFD (MANN) (Verified — Dashboard.jsx).
- **Connected-call target:** read and written via `/settings` (`connected_call_target`) with a PUT (Verified — Dashboard.jsx lines ~1203–1217).
- **Meeting mode / logout-all:** coordinated team state, notifications polling; implementation details **Partially verified**.
