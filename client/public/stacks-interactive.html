Full Flow (step by step)

1
Admin opens StationManagement → clicks station row → opens DonorStacksModal (green "S" button).
2
Modal shows count bar: 627 total · 140 in stacks · 487 remaining. 3 tabs: Normal donors / High-tier donors / Stacks.
3
Admin checks donors in Tab 1/2 → clicks → Move to stack → selected rows slide out (left) → fly to stack box (right) → stack count rolls up → remaining decrements.
4
Count bar updates live. Donors move from "Normal donors" tab to "Stacks" tab.
5
Admin clicks stack → View (70) opens detail drawer with donor list + "✕ Remove" per row. Remove animates row back to left pool.
6
Admin clicks Reassign FRO → pick FRO. Backend creates temp grant (scope = stack type, allowed_count = stack size, auto-offset).
7
Backend stamps target_station on stack member rows (for collection attribution).
8
FRO opens My Donors → sees stack chip. Donor list filtered to stack members only.
9
FRO works donors → collection credits to FRO's permanent station. High-tier money shows in admin High Tier view per-target.
10
Admin can revoke/reassign stacks anytime; unassigned members return to "remaining" pool.

Data model (DB)

CREATE TABLE donor_stacks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ngo_id UUID NOT NULL,
  station TEXT NOT NULL,
  name TEXT NOT NULL,
  stack_type TEXT NOT NULL DEFAULT 'normal',
  fro_worker_id UUID REFERENCES workers(id),
  created_by UUID,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE donor_stack_members (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  stack_id UUID NOT NULL REFERENCES donor_stacks(id) ON DELETE CASCADE,
  donor_id INTEGER NOT NULL REFERENCES donor_profiles(id),
  assignment_id UUID REFERENCES fro_assignments(id),
  added_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE (stack_id, donor_id)
);
